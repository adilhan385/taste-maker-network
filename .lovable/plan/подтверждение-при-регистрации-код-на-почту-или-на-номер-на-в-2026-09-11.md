# Подтверждение при регистрации: код на почту или на номер (на выбор)

## Почему письма не приходят

Домен `notify.chefcook.site` подтверждён и почта включена, но **служебная часть отправки писем в проекте не создана** (проверено: таблицы журнала отправки нет). Обработчик писем регистрации ставит письмо в очередь, которой не существует, — поэтому письмо не уходит вообще. Это и есть причина, а не Gmail.

## Что сделаем

1. **Починим отправку писем**: создадим очередь отправки, журнал, автоотправку по расписанию и заново опубликуем обработчик писем. После этого письма регистрации реально уходят с `notify.chefcook.site`.
2. **В письме будет 6-значный код**, а не только ссылка — так же, как в SMS.
3. **Выбор способа при регистрации**: в форме регистрации появится переключатель «Подтвердить по почте» / «Подтвердить по SMS».
   - Почта: после регистрации показываем экран ввода 6-значного кода из письма, проверяем код и входим.
   - SMS: работает как сейчас — код через Twilio на номер.
4. Кнопка «Отправить код заново» с таймером 60 секунд на оба способа.
5. Поднимем часовой лимит писем авторизации, чтобы регистрации не упирались в ограничение.
6. Переводы для новых надписей на EN/RU/KZ.

## Технические детали

| Шаг | Действие |
|-----|----------|
| Инфраструктура почты | `setup_email_infra` (pgmq очереди, `email_send_log`, cron, `process-email-queue`) |
| Шаблон | `_shared/email-templates/signup.tsx`: добавить блок с `token` крупным шрифтом |
| Публикация | `deploy_edge_functions: ["auth-email-hook", "process-email-queue"]` |
| Клиент | `AuthModal.tsx`: состояние `verifyMethod: 'email' \| 'sms'`, шаг `verifyEmail` с `supabase.auth.verifyOtp({ email, token, type: 'signup' })`, повторная отправка через `resend()` |
| Лимиты | `configure_auth` → `rate_limit_email_sent` |
| i18n | `src/lib/i18n.ts`: ключи выбора способа, ввода кода, повторной отправки |

## Важно

Телефон при регистрации остаётся обязательным (уникальность номера сохраняется), но подтверждать пользователь будет один канал — тот, что выбрал.
